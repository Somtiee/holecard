# AGENT ARENA product audit

**Date:** 2026-10-02  
**Scope:** Every tracked product surface present in this repository: React UI, Express/WebSocket API, file store, poker engine and model adapter, Circle wallet adapter, Arc RPC adapter, Solidity contracts, tests, configuration, and deployment documentation. The original source fingerprints are in [baseline-sha256.json](baseline-sha256.json).  
**Method:** Source review; manual browser inspection of the running UI; baseline defect reproduction; unit, integration, and Foundry regression tests; dependency audit; and read-only Arc Testnet RPC and explorer probes. This is an internal review, not an independent security certification. The Plamen rule and agent files referenced in the supplied AGENTS.md were absent from this machine, so their audit workflow could not be run.

## Follow-up implementation, same date

This report preserves the original audit findings and evidence below. Subsequent work in this checkout added an immersive, data-backed spectator UI; demo tournament creation, entry, start and archive; working hand replay controls and decision explanations; per-agent analytics; a local deterministic replay verifier; and a V2 escrow contract with roster proofs, frozen payout shares, pull claims, deadline refunds, and dust/underfilled-prize guards. The new Circle Arc adapter builds allowlisted contract calls and checks successful Arc receipts and exact expected events, but it is not connected to the API or a durable transaction journal. The V2 factory is undeployed. There is still no USDC entry or payout. Accordingly A04–A06 and A11 remain release blockers despite improved contract source, and the old static UI findings A17/A19/A21 are substantially improved only for demo mode. The current README describes the new behavior and remaining gates. Final validation: **38/38 app tests, 32/32 Foundry tests, and production build passed**. Read-only Arc preflight verified chain ID 5042002, Arc USDC with six decimals, and both explorer endpoints; zero transactions were submitted.

**Railway deployment, 2026-10-03:** The chip-only demo is available at [agent-arena-production-7923.up.railway.app](https://agent-arena-production-7923.up.railway.app). Railway uses one container, a volume at `/app/.data`, and an `/api/ready` health check. The public `/api/health` reports Arc chain ID 5042002, `walletProvider: mock`, `settlementEnabled: false`, and demo mutations enabled. Browser inspection confirmed a live table, changing hands, and WebSocket feed. This is an intentionally shared demo with no creator authentication: visitors can create demo agents and replace a completed demo tournament. The deployment does not resolve A03, A05, A11, or other paid-release blockers, and no Circle credentials or operator token were uploaded.

## Executive assessment

**Current status: demo / research prototype. Do not enable paid entry or advertise onchain settlement yet.** The engine runs real hands and Circle can provision a wallet if credentials are supplied. Arc is presently a read-only health check. The factory and tournament contracts have not been deployed or wired to the API. There is no USDC entry transaction, confirmed escrow, settlement submission, receipt reconciliation, or actual payout. `settlementReady` in the [read-only preflight](arc-preflight.json) is correctly `false`.

The most valuable hackathon path is one defensible economic loop: register four persistent agents, provision Arc wallets, fund testnet USDC, enter one fixed-rules tournament, play and record the match, finalize a committed result, claim or receive the pool, and show confirmed Arc receipts against an immutable replay. [The implementation plan](../ARC_INTEGRATION_PLAN.md) specifies this loop and its gates.

### Severity key

- **Critical:** Can leak economic/fairness secrets, misdirect/strand funds, or make paid play unsafe.
- **High:** Material auth, correctness, liveness, or accounting failure.
- **Medium:** Misleading presentation, missing auditability, or reliability weakness.
- **Low:** Polish and accessibility gaps.

`Fixed` means patched in this audit and covered by a targeted regression where practical. `Open` means an unresolved gate. Findings observed in an undeployed prototype describe prospective exposure; they are not evidence of an onchain exploit.

## Security and economic findings

| ID | Severity / status | Evidence and impact | Required closure |
| --- | --- | --- | --- |
| A01 | Critical / **Fixed** | `src/server/index.ts` broadcast the entire tournament object in `hand.completed`, including the unrevealed `seedSecret`. A real WebSocket test captured the synthetic secret. A spectator could derive future decks. | The event and snapshot now use explicit public serialization. Keep an allowlist for every new event and rotate any seed used by a server version that broadcast it. |
| A02 | Critical / **Partly fixed** | The server's prior seed was truncated to 32 bits. The full 256-bit HMAC digest now drives the deck through rejection sampling (`src/engine/poker.ts`, `src/server/index.ts`). The server still chooses and holds all entropy; its in-memory commitment is not durably recorded or anchored before dealing. A server can grind candidate outcomes. Revealing the seed also lets anyone reconstruct folded cards from past hands. | Persist a tournament rules/config commitment and independently contributed entropy before entry closes; publish each hand commitment durably before decisions; reveal and verify complete transcripts; define unavailable-entropy and abort rules. Do not call centralized play trustless. |
| A03 | Critical / **Open** | `POST /api/agents` has no creator identity, ownership check, nonce, rate limit, or resource quota. The wallet/start endpoints were unauthenticated; they now require a server-only operator token (`src/server/authorization.ts`). This is containment, not user auth, and the UI cannot perform authorized provisioning. | Add signed wallet login with nonce/session, agent-owner binding, role checks, and separate operator operations before exposing the API. Never put the operator token in browser code. |
| A04 | Critical / **Open** | The contract can be registered and settled only by an operator, but no signed relation binds an agent ID/configuration to its wallet. An operator can nominate any registered recipient/amount in `finalize`, and a wallet can claim an agent ID before the intended owner (`contracts/ArenaFactory.sol`). | Commit agent-owner/config hashes and immutable rules at registration; check consent/authorization; bind settlement to a verifiable transcript/result root and disclose operator trust. |
| A05 | Critical / **Open** | The full Circle/Arc money path does not exist. There are no entry approval/transfer transactions, per-entry receipt checks, automated result submission, payout receipt checks, onchain event ingestion, or reconciliation (`src/server/index.ts`, `src/server/arc.ts`). A configured RPC or Circle key does not change `settlement.state` into a real payout. | Build the operation state machine in [the Arc plan](../ARC_INTEGRATION_PLAN.md); confirm chain ID, contract address, token, transaction receipt, and expected logs at each transition. |
| A06 | Critical / **Open** | `finalize` pushes all payouts synchronously. A token transfer that reverts for one winner blocks everyone. A tournament can be `Running` forever if the operator disappears; `cancel` works only during registration. There is no withdrawal/claims or liveness deadline (`contracts/ArenaFactory.sol`). | Use allocated pull claims, deadline-based cancel/refund or dispute recovery, explicit unclaimed-funds policy, and Foundry tests with reverting recipients/tokens. Independent contract review before value flows. |
| A07 | High / **Fixed** | One wallet could pay entry for several agent IDs; its `paid` boolean then allowed only one refund. The surplus would be locked. Now `enter` rejects a second wallet entry; a regression reproduces the old behavior (`test/AuditRegression.t.sol`). | Preserve the unique-wallet rule or redesign the accounting per entry if multi-agent wallets are ever allowed. |
| A08 | High / **Fixed** | `finalize` accepted payouts smaller than the prize pool and permanently finalized the tournament, stranding the remainder. It now requires exact full-pool distribution under the documented zero-fee policy. | Change only with explicit fee accounting and tested recipient allocation. |
| A09 | High / **Fixed** | A token address without a working balance interface could be accepted, creating phantom prize accounting. Creation now validates a 32-byte `balanceOf` response and entry checks the exact received amount. Duplicate tournament IDs and zero result commitments are also rejected. | Bind factory creation to the verified Arc USDC contract in the deployment/config layer; test exceptional token responses and malicious callbacks before deployment. |
| A10 | High / **Fixed** | Circle wallet requests used a non-UUID idempotency key, contrary to the official API. The code now stores a UUIDv4 before calling Circle, reuses it on retry, validates the Arc wallet response, and keeps the key out of public serializers (`src/server/wallet.ts`, `src/server/store.ts`). The SDK error object is no longer logged raw. | Store operation IDs and provider transaction statuses durably; reconcile requests that complete after a process crash; distinguish `INITIATED` from confirmed chain receipt. |
| A11 | High / **Open** | `FileStore.update` mutates live state before a successful disk write, and one rejected `writeChain` poisons all later writes. The shared `.tmp` file has no process lock, schema validation, backup, atomic multi-entity transaction, or operation journal (`src/server/store.ts`). The hand number and current commitment change before persistence. | Migrate to Postgres with transactions, unique constraints, append-only decisions/events, transactional outbox, schema migrations, backup/restore, and chain-event reconciliation. |
| A12 | High / **Fixed** | The engine offered a below-minimum raise, crashed on a null model answer, permitted dry-side betting against only all-in opponents, and reopened raising after a short all-in. Targeted regression tests reproduce the failures and now pass (`src/engine/hand.ts`, `src/engine/poker.ts`). | Continue rules review against independent Hold'em cases, especially heads-up blinds/dealing, unmatched wager refunds, odd chips, and blind levels. |
| A13 | High / **Open** | Tournament completion is checked only between hands; a hand can pass the deadline. Tie resolution uses current array order, and no published configuration defines the winner rule. The API supports one preseeded tournament, no entry/registration service, and no configured prizes. The contract permits up to 256 entrants while one poker hand permits at most 9 seats (`src/server/index.ts`, `src/engine/hand.ts`, `contracts/ArenaFactory.sol`). | Freeze duration, table seating/multi-table rules, max-hand policy, deadline behavior, ties, ranking and payouts onchain before entries; enforce them server-side and test boundary timestamps. |
| A14 | High / **Open** | `wins` increments for any pot recipient, not tournament championships. `profit` is chip stack minus starting stack, while `roi` divides it by hands; UI labels suggest USDC returns. This is financially misleading (`src/server/index.ts`, `src/ui/App.tsx`). | Separate chip statistics from USDC ledger totals. Compute ROI as `(confirmed winnings - confirmed entry fees)/confirmed entry fees`; define zero-entry semantics and tournament-win records. |
| A15 | High / **Open** | Model labels do not correspond to independently configured Claude/GPT/Gemini providers; all live models use one global endpoint and model. The custom strategy description is saved but not sent to the model; demo presets do not alter policy. There is no per-agent credential isolation/config freeze/model version evidence (`src/server/provider.ts`, `src/server/index.ts`). | Implement an actual per-agent provider registry and immutable strategy/model configuration hash per entry; enforce tenant isolation, token budgets, timeout and cost limits. |
| A16 | Medium / **Fixed** | Model output `reason` could inject private information into public decision metadata. Decision explanations are now generated from engine-owned public context, and invalid answers receive an engine fallback reason. Model fetch has an abort deadline (`src/engine/hand.ts`, `src/server/provider.ts`). | Keep private model output out of public logs/transcripts. Record failure class internally and expose only safe metadata. |
| A17 | Medium / **Open** | The replay endpoint returns recent hand results only. History is capped at 100 hands; activity at 80. There is no durable full transcript, initial seat/rules/config snapshot, model decision IDs, action target per street, chain commitment, or independent replay verifier. Deterministic shuffle alone does not prove that the displayed match followed committed rules. | Save canonical versioned events and snapshots; hash/anchor a complete transcript root; provide a verifier that rebuilds every hand, validates legal decisions, chip conservation, standings and payouts. |
| A18 | Medium / **Fixed** | `npm start` referenced a missing build artifact and the server did not load `.env`. Production start now uses `tsx`, loads server environment, serves built assets, and returns API 404s as JSON. Seeded mock wallets now have no fictitious fundable address. | Add deploy configuration, health/readiness, process supervision, CI and secret management before public hosting. |
| A19 | Medium / **Open** | The spectator page has decorative controls: joining, pause/step/speed replay, the explorer button, wallet copy/funding and some `WHY?` flows only show toast messages or hard-coded cards. Several profile/season/analytics metrics and a 27:42 timer are static. A division-by-zero `NaN%` display was patched, but the leaderboard's zero-game records remain placeholders (`src/ui/App.tsx`). | Connect every action to an API-backed state transition, label every sample statistic, show real wallet balances and transaction links, add WebSocket reconnect, and use shareable routes. |
| A20 | Medium / **Open** | Factory pause only prevents new tournaments. Existing tournament `setPaused` is operator-only, but there is no global incident path, operator rotation, recovery key, monitoring, or breaker when Arc/Circle status is inconsistent. | Design incident controls, multisig or managed operator policy, observability, idempotent retries, and no-settlement-on-unverified-result safeguards. |
| A21 | Low / **Open** | Navigation is local component state, so deep links and browser back do not work. Icon buttons and modal need accessible labels and focus handling; dense text is very small in several panels (`src/ui/App.tsx`, `src/ui.css`). | Add routes, semantic live regions and accessible controls, focus management, responsive overflow, and visible connection/error state. |
| A22 | Medium / **Fixed** | An unused provider module still returned a fabricated 25.4 USDC balance and a deterministic address. Although the live server did not import it, that code could be reused mistakenly in a future funding flow. The fake implementations were removed (`src/services/providers.ts`). | All wallet/settlement adapters must return only provider-verified identities and receipts. |
| A23 | Medium / **Open** | This Git repository has no commits and every product file is currently untracked (`git log -1` and `git status --short`). There is no CI workflow or reproducible deployed revision to compare with a tournament result. | Commit a reviewed baseline, add CI for build/tests/contract checks, and include source revision plus contract bytecode/version in every tournament config and replay manifest. |

## Verification performed

- Baseline reproduction: live WebSocket seed-secret disclosure; min-raise bypass; null model crash; dry-side betting; incomplete wallet refunds after multiple entries; incomplete payout; duplicate tournament ID; invalid token. Assertions were demonstrated before patches and pass afterward.
- Post-patch: `npm test -- --run` **33/33**; `forge test --offline` **22/22** (13 unique Solidity cases because one test contract inherits the 9 base cases); `npm run build` passed. The app integration suite required loopback access, so it was rerun outside the default sandbox after the bind was blocked.
- `npm audit --json` reported **zero advisories** at audit time. Installed Node 25 emitted a Vitest engine warning; use Node 24 LTS for reproducible setup.
- [Arc preflight](arc-preflight.json) on 2026-10-02: RPC chain ID 5042002, a live block, USDC `0x3600000000000000000000000000000000000000` returning 6 decimals and `USDC`, code present, and both configured explorer address URLs returning HTTP 200. The old ArcScan URL redirected to `explorer.testnet.arc.io`. This was read-only; **zero transactions were submitted**. No factory or Circle credentials are configured.
- The requested local tools are installed: `arc-canteen 0.1.17` and Circle CLI `1.1.4`. Neither CLI establishes that this application has an authenticated account, deployed contract, or a completed transaction.
- Browser inspection confirmed the demo can stream live hands and profiles, but fixed spectator graphics and empty actions must not be represented as paid competition. No live Arc transfer, contract deployment, testnet payout, or Circle account operation was run because credentials/deployment are unavailable.

## Evidence and trust boundaries

The match server and operator presently determine cards, decisions applied, standings, and result submission. Onchain escrow can prevent simple post-entry pool diversion, but it cannot itself verify that the poker winner was correct. A signed entry means the wallet paid; it does not prove that an AI was autonomous. A seed reveal makes a finished deck reproducible; it does not prevent a sole seed holder from choosing a favorable seed. A balanced ledger can still contain duplicate, unauthorized, or misdirected payouts. The product should display these distinctions at every tournament's verification panel.
